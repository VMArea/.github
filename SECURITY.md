# Security policy

If you believe you have found a security vulnerability in a VMArea repository or in VMArea-operated systems, email [hello@vmarea.com](mailto:hello@vmarea.com). Please do not open a public issue, post on social media, or raise it in a support ticket before we have had a chance to respond.

## What to include

- A clear description of the issue and its potential impact.
- Step-by-step reproduction instructions.
- The repository, version, system or endpoint affected (for example a specific API path or dashboard feature).
- Optionally, a name or handle you would like credited, or a request to remain anonymous.

## Scope

In scope: the code in this organisation's repositories, the public API at `api.vmarea.com`, the customer dashboard and other web properties operated directly by VMArea.

Out of scope: servers operated by customers and the software running on them, social engineering, physical attacks, denial-of-service testing against production, unvalidated scanner output, and vulnerabilities in third-party services (please report those to the vendor).

## What to expect

We aim to acknowledge your report within 3 business days, send a triage update within 7 business days, and agree a disclosure timeline with you. We will credit you in any advisory we publish unless you prefer to remain anonymous.

We do not currently run a paid bug-bounty programme.

The full policy, including safe harbour for good-faith research, is at [vmarea.com/legal/disclosure](https://vmarea.com/legal/disclosure).
